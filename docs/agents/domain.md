# Domain Docs

This is a single-context repository.

## Before exploring

- Read `GLOSSARY.md` at the repository root.
- Read relevant decisions in `docs/adr/` before working in the affected area.
- If either is absent, proceed silently. Create domain documentation through `/domain-modeling` when terminology or decisions are resolved.

## Vocabulary and decisions

Use the glossary terms in issue titles, proposals, code and tests. When a needed concept is missing, check existing project terminology and note a real gap for `/domain-modeling`.

If a proposal conflicts with an ADR, name the ADR and explain why the decision should be revisited before overriding it.
